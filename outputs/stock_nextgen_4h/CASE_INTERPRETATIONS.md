# 四小时案例解释：输入改善为什么没有稳定转化为方向提升

本页解释 `runs/v1/CASE_NOTES.md` 的固定案例。案例槽位在读取标签前定义，具体窗口按键哈希确定；随后才附加实际方向。新闻标题和正文没有进入 Git，本页只写释义。案例由助手检查，没有独立组员复核，不能用这些定向案例估计总体错误比例或证明新闻导致价格变化。

## 怎样区分错误

| 层次 | 本轮怎样判断 | 不能据此声称什么 |
|---|---|---|
| 输入错误 | 有新闻，但目标公司段落选择器没有留下合格内容，或留下的主要是历史／比较背景 | 不能因此断言原新闻没有目标公司信息 |
| 段落选择变化 | P0 与 P1/P2/P3 跨过 0.5 的方向不同 | 不能仅凭方向改变判断哪段更正确 |
| LLM 预测错误 | 冻结 LLM 的最终 UP/DOWN 分数与四小时标签方向相反 | 二选一接口没有生成理由，因此不能反推模型具体“理解错了哪句话” |
| 市场状态缺失 | 本地没有合格的 SPY/QQQ/行业分钟线，市场分支没有运行 | 这是未观测因素，不是已经证明的错误原因 |
| 最终预测错误 | F6 与实际四小时方向相反 | 不能把融合错误全部归因于某一个输入分支 |

## 跨案例观察

1. **完整段落修复了字符截断，但没有修复任务错配。** P1 的训练期字符断句从106处降到0，然而P1训练期平均BA低于P0。公司长期利好、竞争背景和已经发生的价格变化仍未必预测下一段四小时。
2. **增加上下文既改对也改错。** 相对P0，P2在四个股票×时期单元分别产生 `10/7、38/33、22/10、15/19` 个改对／改错。AMZN开发期净改善明显，后续期则净变差。
3. **去重没有提供额外稳定收益。** P2→P3有1,391行输入逐字节相同；真实变化只集中在少数有重复报道的窗口。P3没有在四个单元中一致优于P2。
4. **AMZN首先受覆盖限制。** 804个AMZN窗口中，P1有422个、P2有402个、P3有405个没有合格目标段落；AAPL对应只有6个。模型大小无法补回不存在的输入。
5. **全局融合学到了训练期互补，但迁移不稳定。** March–August选择的F4/F5为正文75%＋LLM25%，F6为LLM50%＋R1 50%。后期F4/F5四个单元BA都高于50%，但没有在四个单元都超过F0并守住Brier；F6在AAPL后续降至49.39%。
6. **近期价格解决了“完整小时太旧”，没有解决非平稳关系。** R1四个单元都高于50%，也都优于R0的BA；但AMZN两段Brier都比R0更差，配对区间也跨0。

这些案例支持当前结论：下一次确认的重点应是冻结一个简单候选并获取未参与设计的新时期，而不是继续利用同一后期标签选择股票专属赢家。
