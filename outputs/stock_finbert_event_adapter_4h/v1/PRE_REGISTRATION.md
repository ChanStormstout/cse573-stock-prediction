# FinBERT event adapter four-hour experiment: pre-registration

Saved before any new event-adapter training, inference, oracle diagnostic, or four-hour residual result was produced.

## Scope and evidence boundary

- The prediction target remains the fixed AAPL/AMZN four-hour direction task with the existing 1,607 window keys and cutoffs.
- September--October (`development`) and November onward (`later`) have already influenced the project and are exploratory historical replays. They are never pooled for model selection.
- The 458 extraction labels are model-provisional dual-GPT labels with assistant adjudication. They are not independent-human gold and cannot establish formal extraction acceptance.
- `ProsusAI/finbert` postdates the 2018 articles, so this is a retrospective course experiment.
- Raw articles, provisional labels, cached tensors, checkpoints, and model weights stay outside Git.

## Fixed extraction data protocol

- Article split: January--February `train` (249), March `development` (87), April `check` (122).
- Exact event groups and the sealed duplicate links are audited before training. Any connected duplicate component crossing a split stops the run.
- Each input contains `TARGET=AAPL` or `TARGET=AMZN`, the title, and each numbered complete candidate sentence from the target-company context. The implementation clarification in `PROTOCOL_AMENDMENT.md` protects the candidate as the first sequence and supplies all other numbered target-company passage sentences as the second sequence. Only that context may be token-truncated at the 512-token model limit; evidence sentence IDs remain attached.
- Gold tasks are limited to fields that exist in the sealed labels: evidence sentence, event existence, event type (`rating`, `target_price`), and action (`raise`, `lower`, `maintain`, `initiate`, `unknown`). Old value, new value, and unit are never generated by FinBERT; deterministic rules may copy and validate them from a selected evidence sentence.
- A sentence may support rating and target-price facts simultaneously. No selected type above threshold means `no-event/unknown`.

## Train-only chronological selection

Three expanding forward folds are fixed:

1. train through 2018-01-15; evaluate 2018-01-16 through 2018-01-31;
2. train through 2018-01-31; evaluate 2018-02-01 through 2018-02-14;
3. train through 2018-02-14; evaluate 2018-02-15 through 2018-02-28.

The three seeds are 573, 574, and 575. All configurations use the same folds, sentence inputs, task losses, training-only class weights, and seeds. No best seed is selected. Evidence thresholds are chosen globally from `{0.35, 0.50, 0.65}` using pooled train-forward predictions only.

Adapter selection score is fixed as:

`0.40 * article event F1 + 0.20 * type macro-F1 + 0.20 * action macro-F1 + 0.20 * evidence micro-F1`.

The mean score across seeds selects one adapter configuration. Ties within 0.002 prefer fewer trainable parameters in the order A0, A2, A1. March and April extraction results cannot affect this choice.

## Fixed FinBERT configurations

All heads are trained jointly with weighted cross-entropy. Maximum epochs are 12, batch size is 16 sentence units, gradient clipping is 1.0, early-stopping patience is 2 evaluations, and the seed-mean selected epoch count is used for the full January--February fit.

- **A0:** frozen FinBERT encoder; train two type-specific evidence heads and two type-specific five-action heads; head learning rate `5e-4`, weight decay `1e-4`.
- **A1:** same heads; unfreeze encoder layers 10 and 11; encoder learning rate `1e-5`, head learning rate `5e-4`, weight decay `1e-4`.
- **A2:** same heads; freeze the base encoder and add rank-4 LoRA updates to query/value projections in encoder layers 10 and 11; LoRA alpha 8, LoRA/head learning rate `1e-4`/`5e-4`, weight decay `1e-4`.

The check set never selects an epoch, threshold, or configuration. Checkpoint reload must reproduce stored probabilities within `1e-6`.

## Extraction comparisons

Report event precision/recall/F1, event-type and action macro-F1, evidence selection, no-event false-positive rate, AAPL/AMZN slices, coverage, and nonduplicate event counts. Existing rule, Qwen3-1.7B ordinary/gated QLoRA, and frozen Qwen results are reused only when their evaluation rows and label fingerprints match; any incomparable field is marked unavailable rather than reconstructed.

## Four-hour oracle diagnostic

- Map sealed provisional events to fixed four-hour windows by record key and availability cutoff.
- Articles absent from the 458-label set are `unknown`, never negative.
- Use F1 train-forward OOF probabilities as the base. The diagnostic can use sealed March/April labels because those dates are inside the stock-training period, but it remains a coverage-limited, nondeployable field-utility upper-bound diagnostic.
- Fit residual candidates only on past OOF rows and evaluate chronologically. If fewer than 30 unique accepted events or 60 event windows are available for a stock, its independent residual is disabled.
- If the provisional oracle does not improve mean forward-fold BA at the fixed Brier guardrail (`delta Brier <= 0.002`) in at least two evaluation months, do not expand the adapter grid beyond A0--A2.

## Deployable residual protocol

The base probability is F1 (price plus full text) when the fixed pipeline has reliable text and R1 otherwise. Let `g=1` only when an extracted fact passes target, evidence, action, and applicable numeric checks. For every `g=0` row, the saved final probability must equal the base probability exactly.

`logit(p_final) = logit(p_base) + g * delta_s(z)`

The event vector has at most 20 fixed features: counts by type/action, signed target-price change when old/new values validate, missing-value indicators, duplicate-report count, and event age. Residual L2 logistic candidates use `C in {0.01, 0.1, 1}` and are selected only from March--August chronological OOF predictions with the same primary rule: highest mean monthly BA subject to mean Brier worsening no more than 0.002; ties choose lower C.

Compare:

- C0: shared residual;
- C1: independent per-stock residual, only where both event-count minimums pass;
- C2: shared event effects plus L2-shrunk stock-specific event interactions.

Select one parameterization globally across both stocks from train OOF; never choose a stock-specific winner from development or later results.

Methods are D0=R1, D1=F1 with strict R1 fallback, D2=D1+rule facts, D3=D1+A0 facts, and D4=D1+the training-selected adapter facts. Existing F0, R1, F1, F2, and F6 are copied from the fingerprinted next-generation run for matched comparison.

## Reporting and stopping

- Report train-forward OOF, development, and later separately for AAPL and AMZN: BA, MCC, Brier, monthly results, coverage, constant-prediction rate, changed-right/changed-wrong, one-day and five-day paired block intervals, and seed mean/spread where applicable.
- Cases are fixed by semantic cohort before revealing downstream correctness: historical/current confusion, maintained rating with changed target, multi-company target mismatch, duplicate reports, correct extraction/wrong prediction, extraction error/wrong prediction, and exact no-event fallback.
- Two targeted adapter configurations without extraction improvement stop any model-size expansion. Better extraction without four-hour gain is reported as better understanding without verified direction increment.
