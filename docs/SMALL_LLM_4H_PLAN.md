# 小型 LLM 事实抽取 → 四小时预测：实施方案

日期：2026-09-16。状态：**方案与本机可行性核验完成；新抽取、微调、四小时下游实验尚未执行。**

## 1. 决策与已有证据

推荐把小型 LLM 作为有证据的事实抽取器，先建立冻结模型对照，再有限尝试任务监督微调；保持当前四小时价格＋文本底座，不让 LLM 直接猜涨跌。抽取好不等于预测好，分别验收。

已读现有源代码与结果：`outputs/stock_events/pilot_v3.py`、`results/pilot_v3_summary.json`、`events.py`。40条输出中 earnings 37条、product_business 3条；earnings是第一选项。单字母限制保证格式，并不保证理解；位置偏差是待检验假设，不能认定为唯一原因。旧试验使用 Qwen3-1.7B-4bit，无任务微调，无全量四小时下游验证。旧错误和已看案例只能作开发材料。

本机读取：Apple M5，25,769,803,776 bytes（24 GiB）统一内存。已有隔离环境 `work/stock-data/structured-env`：MLX 0.32.2、mlx-lm 0.31.3；Metal available=True。MLX报告建议工作集约17.76GiB，这是系统提示，不是已测训练峰值。未运行新训练或测出吞吐。

## 2. 总流水线

```
原新闻＋原时间字段
  → 截止点检查／文本清洗／段落和字符位置编号
  → 目标公司候选段落（保留相邻上下文、标题和导语）
  → 规则 / 冻结Qwen / 同一Qwen+QLoRA 三种抽取器
  → 字段与证据核验、未知与拒绝状态
  → 同公司同事件的过去信息归并、低维事实特征
  → 固定价格＋文本底座概率 + 小型事实修正
  → 全部原定四小时窗口评价、案例与成本报告
```

来源、目标公司、谓词、数值、证据、时间形成可追溯关系表，体现 semantic web mining 中的实体识别、关系抽取、实体消歧和信息溯源。首版不需要 GNN；增加图存储不自动产生新的监督信号。

### 输入：先保证关键事实能被看到

- 禁止只复用曾漏掉关键信息的旧 target 摘录。回到合法保留的原正文。
- 文本清洗后生成稳定 paragraph_id / sentence_id 与原文映射；保留否定、比较对象、修正声明和相邻句。标题与正文冲突时保留双方，不静默以标题覆盖正文。
- 每篇针对 AAPL/AMZN 分别形成输入，避免同一篇对两股复制相同解释。
- 首轮总长度2048 tokens：含任务/示例、输入和最多512输出；预先tokenize计数。输入过长按确定性段落选择或分块，记录截断和证据遗漏；不能让训练器截掉答案尾部。
- 输入检验单独比较“旧摘录”和“新段落”；在助手标注证据上量化候选段落召回率，区分检索失败与阅读失败。
- 少量示例固定为3个短示例（明确变化、无合格事件、他司/背景干扰）；同一输入预算和提示同时给冻结与微调模型，尽量保持除adapter外一致。

### 输出：允许多个事实，也允许无事实

第一版明确限定：分析师评级、目标价调整、业绩/指引中的可核对变化；其他事件保持原文本输入。这个覆盖限制单列报告，不宣布完整金融事件方案已通过。

每条事实字段：目标公司、事件类型、动作、metric、old/new或actual/expected、unit、period、current/background/uncertain、sentence_ids、数值原文span、conflict/unknown状态。发布时间和可用时间从数据附加，不让模型猜首次披露时间。机构首版可为空，不把机构完整关系质量宣称已解决。

例如“维持 Buy，目标价200降至180”必须输出两条事实：rating=maintain；target_price=decrease，旧200新180。程序确认同对象/币种/期间后计算−10%；不要把评级Buy转成预测上涨标签。

管理层guidance、分析师consensus、历史实际值要分开。EPS/revenue actual-vs-expected必须两数均有同期间同单位证据；没有预期值就留空，不凭模型记忆补数据。纯历史复述不等于当前首次披露；无法判断就unknown。

- `events=[]`表示在**给定输入内**没有支持的事实，不保证完整文章绝无事件。
- 程序核验JSON/schema、公司、证据id/span、数字/单位/期间、重复与冲突。算术由程序完成。
- 原文包含这些词是必要条件，不足以证明关系正确；关系质量仍需审阅。
- 无效输出最多一次固定格式修复，规则对冻结/微调一致；记录第一次成功率、修复率与最终通过率，不无限重试直到“满意”。
- 真正的语法约束解码需先验证运行库支持；“提示输出JSON”不得称为保证合法JSON。

## 3. L00：先做有限诊断，不先扩大模型

从过去训练期选48—64个非重复文章—公司对，覆盖明确事件、他司、持仓、历史回顾、无事件、评级与目标价冲突、数字缺失。它们是开发诊断，不是独立最终检查。

顺序进行单因素小对照，不做全组合：

1. 复核原单字母输出；在同输入上循环打乱类别→字母映射，检查预测是否跟着第一位置移动；类别分布和证据支持一起看。
2. 改为可读字段/多事实JSON；同样输入看是否仍坍塌，区分分类设计问题。
3. 固定输出与模型，对比旧摘录与新段落；少量“人工给出正确证据”的输入只作诊断上界，不能作为可部署预测结果。
4. 在24个固定难例上对照4bit/8bit同源权重；需要严格控制revision。若高精度明显改善，再决定是否保留；否则不扩大精度网格。
5. 仅在24例上检查thinking模式。thinking用官方支持的采样建议并给足独立输出预算，不以单token或greedy方式强行限制推理；记录成本，不称为同算力对照。主线仍优先非thinking结构抽取。

这一步区分输入、标签顺序、输出设计、模型适配和量化问题。两版针对性修复仍未达到可用质量则停止批量推理，不能因换成LLM便绕过门槛。

## 4. L01：监督数据如何准备

建议目标为300—600个**真实非重复、可用的文章—公司样本**，这是标注预算，不是已拥有的合格数据。先清点早期数据是否足够。AAPL/AMZN共用一个抽取器，可增加AMZN训练抽样，但检查集须另报自然分布。

- 约三分之一为负例/未知/他司/背景；同时加入混合动作、多事件、正文更正。比例是起点，由真实分布和覆盖审计决定。
- 每条：原文与目标公司、段落映射、JSON标签、证据、标注者、修改历史、available_at、近似事件组、用途和哈希。标注界面隐藏后续价格/标签。
- 助手可起草标签；规则只负责预填和校验，不能把规则或模型生成标签直接当独立金标准。双读/自审仍不是独立组员复核。
- 分割先按事件组，再按可用时间。转载、同篇两公司样本和同一事实的改写绑定组，不随机打散行。跨边界组从后侧检查中排除/隔离并记录；历史信息分组只使用当时可知证据。
- 已用于修改提示词/规则的40、65或其他案例均登记为已暴露；真正检查组不参与提示或checkpoint选择。
- 微调开发集与最后质量检查集分开；每拟用事件类型至少30个非重复独立检查例，关键字段正确率至少90%，另报漏抽、coverage、误抽、样本数及区间。90%是工程门槛，不是性能保证。
- 暂定标注可用于开发/本地微调试验；缺少独立检查时完整关系分支保持未验收，不批量接入正式结果。若另立有限字段探索协议，必须明确它不能替代完整验收。
- 合成数字/公司替换可作少量训练增强或回归测试，但算术与实体证据必须相容；不能混入真实检查集、伪装新独立事件或为了平衡捏造缺失数据。

### 特别重要：抽取器本身也有时间边界

最省计算、最清楚的主协议是**尽早适配后冻结**：先检查1—2月是否够作训练/开发与锁定检查，够则在2月底前冻结抽取器及few-shot示例；从3月起建立前向下游账本，6/7/8月做开发期前向比较。冻结点后的文章与价格标签不得参与抽取适配。

如果早期数据不够，延后冻结点并明确减少可用前向折；不能用1—8月训练的抽取器给6月做“严格过去预测”。对于底座本身可继续用此前全部价格/文本训练，事件修正仅用冻结后已成熟的样本外数据。所有开发/后续评价窗口仍保留，证据不足时回退。

若未来要每折重训抽取器，需分别生成只使用该内折过去内容的特征和标签账本；禁止一份全时期adapter在所有折复用。这属于新增计算预算，首版不做。

现代基座可能接触历史新闻，是事后表示工具；上述纪律只能控制本项目适配和监督，不能认证基座无历史记忆。

## 5. L02：如何在M5上做真正的QLoRA

使用同源 `Qwen3-1.7B` 的固定4bit MLX基座；优先复用已缓存revision，保存tokenizer/config/权重哈希。为公平对照，冻结版本与微调版本使用相同量化、输入和解码设置。

QLoRA在这里指冻结量化基座，只训练低秩adapter；MLX的量化实现不应宣称为原论文NF4配置的完整复现。不是全参数训练，也不是继续用股价标签训练Qwen。

初始规格（工程起点，不是最优值）：

| 项 | 设定 |
|---|---|
| 模型 | Qwen3-1.7B 4bit，同源固定revision |
| 可训练层 | 最后8个Transformer block的self_attn.q_proj/v_proj；运行前核对层名与参数量 |
| LoRA rank | 8 |
| MLX scale / dropout | 16 / 0.05；scale按MLX实际实现解释，不能照搬PEFT alpha |
| 学习率 | 首次1e-4；只有开发质量显示不稳定才对照5e-5 |
| micro-batch / 梯度累积 | 1 / 8，等效8个样本后更新 |
| 最大总长度 | 2048 tokens，含输出；先确认标签不被截断 |
| 显存节约 | 梯度检查点开启，短段落、顺序运行 |
| epoch | 最多3遍真实训练样本；实际iters按库的micro-step定义计算并记录已见样本数 |
| 评价与保存 | 每半个epoch与epoch末保存，使用开发字段/事实指标挑checkpoint；不只看生成loss |
| 种子 | 573先验证可用；最终匹配对照573/574/575，不挑最好种子 |

训练目标是assistant输出JSON token的交叉熵，mask掉输入新闻/提示/示例；不要训练模型复述新闻或优化后来股价标签。正确的证据句id和数值作为JSON监督的一部分；不训练/索取思维链文本。

**本机发现需要专门处理的实现点：** mlx-lm 0.31.3 `ChatDataset.process` 默认apply_chat_template未显式传 `enable_thinking=False`。需要项目内受控tokenize/loader，在完整样本和prompt-only两处使用同一模板参数，精确计算assistant mask边界；不能仅在生成时关闭thinking。对token前缀、mask位置、JSON尾部/EOS和截断做回归测试，不修改site-packages来掩盖问题。

先用8个已核对样本做20—50个训练micro-step的工程smoke test：验证adapter非零梯度、权重hash改变、基座hash不变、loss有限、保存重载输出可复现。这个拟合小批次不证明抽取或预测有效。

再跑真实训练并保存：参数量、loss曲线、生成质量、每步耗时、峰值内存、训练样本/事件组数、所有候选、失败日志、adapter和配置。adapter保留本地，不纳入Git；无原文的汇总结果经清单入库。

本地判断：1.7B/4bit与上述小batch规格适合先在24GiB M5尝试；不能保证未跑配置的峰值和工期。先测50步，根据真实每步耗时估算所有种子+推理成本。持续交换内存、内存错误或完整阶段预计超过约2小时，才评估转Sol；迁移需要同源模型/种子与量化差异记录，MLX adapter不能默认与CUDA PEFT文件直接互换。

## 6. L03：如何进入四小时预测

### 保留原有底座，事实仅作修正

主底座固定为当前价格＋标题TF-IDF＋L2 LR，全文联合模型继续单列已登记参考；不依据后续成绩为两股换底座。

设底座概率为p0，事实特征z，g表示有通过质量/证据条件的事实：

`p = sigmoid(logit(p0) + g * lambda * beta^T z)`

- 修正器无自由截距；其监督输入是严格前向生成的底座样本外概率，底座不重训为事件专用模型。g=0时直接return p0，要求逐元素精确一致。
- z<=20维，保留评级动作、目标价百分比、EPS/revenue相对明确预期差、guidance变化、支持数与冲突/未知指示。预算不足先删特征，不加宽网络。
- 同事件按可用时间归并一次，评级和目标价保留不同事实；所有方法相同候选文章与规则。
- 先用已登记的固定时效（披露年龄proxy、未知标记、收缩分母1+权重和）；不能另搜多种半衰期制造额外自由度。原文未知首次披露时间不补猜。
- L2强度用C={.01,.1,1}，lambda={0,.25,.5,1}；均只在嵌套过去月份选。lambda=0明确允许拒绝事实增量；不放松既定Brier约束迎合后续分数。
- 底座OOF→修正拟合→lambda选择要分层。每个外折只用更早的OOF记录训练/选择，标签end必须早于下次拟合。若只有很少月份可用，减少折数并披露，不在同段训练和调lambda。
- 每股至少30个非重复接受事件、60个事件窗口方可训练专用修正器；不够则保持底座。训练可合并两股抽取样本，但不能声称合并创造了AMZN新新闻。

### 核心对照表

| 组 | 相同底座上增加什么 | 用途 |
|---|---|---|
| B0 | 无 | 原模型参照 |
| B1 | 规则事实修正 | 字段/聚合收益 |
| B2 | 冻结Qwen+few-shot事实修正 | LLM理解增量 |
| B3 | 同一Qwen+QLoRA事实修正 | 任务适配增量 |

三抽取器输入文章/段落预算相同，时间、下游特征模板与参数预算相同。抽取率不同本就是机制结果，必须全窗口评分并报覆盖；再补共同接受事件子集的诊断，不能用子集结果替代全体。增加一个仅保留“事件存在/数量”的匹配消融，区分覆盖/数量与动作数值含义的贡献。

如改为原模型＋事实拼接联合重训，应另列实验，不能与固定修正混为一谈，也不能把它在无新闻窗口的价格系数改变称为LLM理解收益。

## 7. 评价、解释与停止条件

抽取层：候选段落证据召回、schema通过、目标归属、动作、数值/单位/期间一致、证据支持、完整事实precision/recall、无事件误报、冲突/unknown与覆盖；分股票/事件/正文长度。loss下降不替代这些指标。

预测层：原定全部窗口BA/MCC/Brier、两股分月结果、上涨/下跌召回、新闻与无新闻覆盖、固定种子波动；共同交易日配对重采样和5日块敏感性。所有历史分数仍为探索性回测。

案例：先固定选取改对/改错/共同对/共同错的分层规则，隐藏股价结果检查候选段落→LLM→证据核验，再揭示预测；区分检索失败、对象/关系误读、数值错误、已读对但与4h结果无关。不能靠少量好案例证明涨分。

停止：输入遗漏优先修输入；抽取格式差先修模板/输出；抽取明确改善但完整窗口预测无稳定增量，不继续加大模型或盲目多epoch。两次针对性版本无收益就总结。关键语义质量未过时停止全量批处理，保留基线与失败记录。

## 8. 执行批次与交付

1. L00：早期语料/监督数量盘点、模板/字母位置/输入诊断，冻结schema和时间协议。
2. L01：标注与按事件组切分，冻结小模型基线质量和独立复核材料。
3. L02：20—50步工程核验，再正式QLoRA；报告质量变化与真实运行成本。
4. L03：质量与样本条件满足后B0—B3匹配四小时回测、案例、报告、demo。

代码目标接口：prepare_inputs → label_and_split → extract_frozen / train_adapter → validate_facts → aggregate_features → fit_fact_offset → evaluate → report。每次独立目录，缓存纳入原文、时间、提示、tokenizer、基座revision、量化、adapter、schema和聚合哈希；恢复先检查停止状态。

更新PROJECT_LOG与审阅入口，按仓库清单公开不含新闻原文的代码/配置/指标；不上传原始标注新闻或大权重。
